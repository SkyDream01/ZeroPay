# ZeroPay 零点收银

中文安卓条形码收银与仓储管理应用。Android 8.0 及以上；原生 Java 界面、SQLite 本地存储，离线使用，无账号和服务器。

本项目采用 [GNU GPLv3 开源许可证](LICENSE)（`GPL-3.0-only`）。

## 界面

采用 Material Design 3 原生组件：绿色主题、带选中指示器的底部导航、填充 / 色调按钮、浮动标签输入框、圆角卡片和确认对话框。浅色与深色外观跟随系统；收银合计与确认收款固定在页面底部。

## 功能

- 收银：相机扫描商品条码/二维码、手输条码、回车结尾的 USB/蓝牙 HID 扫码枪；商品搜索选择、修改购物车数量、现金找零。
- 促销：本单整单打折、满减或自定义价格，实时显示商品原价、优惠与应收；订单和销售导出保存促销快照。
- 商品：唯一条码（保留前导零）、名称、分类、单位、售价、成本、库存预警。
- 套餐：保存固定商品组合、每套数量与组合售价；支持套餐和单品混合收银，按组成商品扣库存和整单退货。
- 仓储：采购入库、领用/损耗出库、盘点实际库存，记录数量差异和原因。
- 订单：明细查询、整单退货恢复库存，防止重复退货。
- 数据：CSV 商品导入、商品模板与库存导出、销售明细及库存流水导出。导入先校验并预览，再以事务统一写入。
- 金额以整数分存储，销售与库存变更在同一个数据库事务提交；禁止负库存。
- 购物车保存在本地，切换页面或重启应用后保留；结账再次核验价格与库存。

## 使用

1. 在「库存」创建商品并填写初始库存，或在「数据」导入 `samples/products.csv`（示例商品，请按实际修改）。
2. 扫码或输入条码加入购物车；未知条码可新建档案。
3. 选择收款方式、确认实收金额，完成后自动扣库存。
4. 采购、损耗和盘点使用「库存 → 入 / 出库」。
5. 在「流水」查看订单、办理整单退货，在「数据」导出 CSV。

微信、支付宝、其他方式只记账，须先在外部工具核实收款；退货只恢复库存并标记订单，需自行办理资金退款。不接入支付网关，不包含多店同步、打印、会员、部分退款或历史订单导入。

## 促销使用

购物车加入商品后，点击清单下方「促销：无促销」，选择整单打折、满减或自定义价格，确认后按优惠后的金额收款。

- 整单打折：输入 0.1–9.9 折，最多一位小数，例如 8.5 表示支付原价的 85%；整单应收四舍五入到分。
- 满减：填写门槛和减免金额，达到门槛减一次，不循环满减。未达门槛显示还差金额，按原价结算；减免不可超过门槛，允许满额全免。
- 自定义价格：直接输入本单应收金额，支持 0–1000000 元、最多两位小数，0 元表示全免。修改数量后保留设定金额；若商品原价合计低于设定金额，则按原价收款，优惠不会为负数。
- 每单只能选择一种促销，不叠加；选择「无促销」可取消。修改数量会重新计算，切页和重启保留，清空购物车或完成结账后重置。
- 订单详情保存商品原价合计、优惠和促销说明；整单退款以优惠后的订单金额为准，库存按原数量恢复。
- 升级到 1.1.0 自动保留原数据库；历史订单的优惠为 0。当前功能为本单手动促销，不含活动排期、优惠券或商品级促销。

## 组合售价（固定套餐）

1. 在「库存 → 套餐管理 → 新建套餐」填写名称和组合售价，点击「添加组成商品」选择商品并填写每套数量。例如茶 2 瓶 + 面包 1 个，组合售价 12 元。
2. 在「收银 → 选择套餐」加入购物车，可修改套数，也可同时购买单品或其他套餐。
3. 套餐没有独立库存，收银会合并所有套餐和单品的商品用量检查库存；结账按组成商品数量扣库，整单退货恢复实际扣减的商品数量。

- 套餐可编辑、删除；编辑后购物车按最新定义计算，删除会移除购物车中的该套餐。历史订单保留成交时的名称、组成、套数和组合售价，后续修改或删除不影响退货。
- 售价支持 0–1000000 元、最多两位小数；每套商品数量为 1–1000000 的整数，编辑时填 0 可移除该组成商品。至少包含一种商品，不支持套餐嵌套。
- 套餐价可以独立于单品价格设定。整单打折、满减、自定义价格在「单品金额 + 套餐金额」基础上计算。
- 销售明细列出实际扣库商品，单品价格及行金额为成交时的单品零售价参考，不分摊套餐价；含套餐订单的明细行金额之和可能不等于订单合计。销售 CSV 的 `subtotal` 是单品与套餐合计，`discount` 是额外整单优惠，`total` 是最终应收，`promotion` 同时保存套餐快照。
- 套餐定义保存在本机数据库，购物车内的套餐切页或重启后保留。商品 CSV 不包含套餐定义；卸载或清除数据会丢失套餐配置。
- 1.2.0 自动升级数据库，保留已有商品、库存和订单。

## CSV 约定

UTF-8（可带 BOM），英文逗号分隔，固定表头：

```csv
barcode,name,category,unit,price,cost,stock,min_stock
0012345678905,笔记本,文具,本,8.50,4.20,15,3
```

金额单位为元（最多两位小数，0–1000000）；库存与预警是 0–1000000 的整数。条码长 1–80 字符，首位字母或数字，其余可含字母、数字、点、横线、下划线。不把二维码内的任意 URL 当商品编号。

字段支持双引号、逗号及换行。重复条码、非法金额、负库存、错误表头会拒绝整个文件，并提示记录位置。最多 50000 条商品、1000 万字符。默认更新已有商品信息但保留已有库存；可在预览中勾选覆盖库存，差异写入流水。新商品使用文件库存，未列出的商品不变。

导出采用 UTF-8 BOM。文本中可能触发表格公式的内容会加前置单引号，导回时还原。用 Excel/WPS 导入时将条码列指定为「文本」，否则前导零可能被表格软件丢弃。不要另存为 ANSI/GBK。

销售 CSV 每行是一条商品明细，同一订单的 `total/paid/change` 会在各商品行重复，汇总订单金额必须按 `order_id` 去重。`line_total` 是商品行金额。`status=已退货` 的行表示原销售已整单退货。今日有效销售额按订单发生日期统计，排除所有已退货订单，不是当日现金流净额。

销售 CSV 末尾包含 `subtotal`（单品与套餐合计）、`discount`（额外整单优惠）、`promotion`（促销说明与套餐快照）。`total` 为优惠后的应收；`line_total` 仍按单品零售价计算，不分摊套餐价和整单优惠。整单字段会随商品行重复，汇总时必须按订单去重。

库存流水 CSV 的 `quantity_change` 为带符号变更量，`stock_after` 为变更后库存。销售/库存流水只用于查账，不可重新导入恢复历史。

数据库在应用私有目录，不申请全盘存储权限、不上传数据。使用系统文件选择器导入导出；卸载/清除应用数据会删除数据库。请定期导出商品、销售及库存流水；商品 CSV 只能恢复商品和当前库存。

## 库存商品管理与竖屏扫描

- 「库存 → + 添加商品」支持填写商品资料、初始库存及扫描条码；商品卡片可编辑、入 / 出库及删除。
- 删除需确认，从库存、商品选择和商品 CSV 导出中隐藏，并移除当前购物车条目；历史订单与库存流水保留，仍可办理整单退货。被套餐引用的商品须先从套餐移除。
- 重新添加同一条码可恢复商品，并保留删除前库存及后续退货数量，忽略填写的初始库存。CSV 导入同一条码也会恢复；默认保留库存，勾选覆盖库存则记录差异流水。
- 收银扫码、库存查询和新建商品扫描统一使用竖屏扫描页面。数据库升级到版本 4，保留现有数据。
